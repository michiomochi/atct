# ゴール作成をヘッダーに移す

日付: 2026-08-20
ゴール: 新しいゴールの作成ボタンをダッシュボードページの一番下からグローバルヘッダーに
移動して

## いまどこにあるか

`Dashboard.tsx:100`。**プロジェクト別ゴール一覧の、いちばん下。** ゴールが増えるほど
下に流れ、ダッシュボード以外のページからは到達できない。

## 決定

### ダイアログで出す

ヘッダーにボタンを置き、押すと**ダイアログ**でフォームを出す。

同日、タスク詳細のモーダルをページに移した。**あれをやめた理由は、回答履歴が
上限なしに伸びて自分の内容を切ったこと**である。**このフォームは 3 項目
（プロジェクト選択・題名・説明）で伸びない。** 同じ理由は当てはまらない。

別ページ（`/goals/new`）にしない理由: 読んでいる画面から離れる。ゴールは
「いま気づいたこと」を書き留める入口なので、離脱のコストが目的に反する。

ヘッダー直下に展開しない理由: **全ページ共有のヘッダーが押すたびに伸びる。**
どのページでも本文の位置が変わる。

### 作成したら、そのページの一覧だけを取り直す

ダイアログを閉じ、**ダッシュボードが開いていれば取り直す。** 他のページでは何もしない。
**新しいゴールへ遷移しない**（読んでいたものから勝手に離れる方が害が大きい）。

### 島をまたぐので、経路は DOM のイベントにする

ヘッダーは `Shell.astro`、ダッシュボードは `Dashboard.tsx`。**別々の島なので
React の props では繋がらない。** 状態管理のライブラリを入れるほどの話でもない。

`window` の `CustomEvent` を 2 つ使う。

| イベント | 誰が出すか | 誰が受けるか | 何のため |
|---|---|---|---|
| `atct:goal-created` | ヘッダーのダイアログ | Dashboard | 一覧を取り直す |
| `atct:form-dirty`（`detail: boolean`） | ヘッダーのダイアログ | Dashboard | **入力中は自動更新を保留する** |

### 入力中の自動更新の抑止を落とさない

**ここが今回いちばん壊れやすい。** 同日「更新が入るとフォーム入力が消える」を直し、
人間の承認を得ている（ゴール `goal 39`）。いまその判定は
`Dashboard.tsx` が `GoalCreateForm` から `onDirtyChange` を props で受けて行っている。

**フォームがヘッダーへ移ると、この props が繋がらない。** 何もしなければ、
今日直した不具合が同じ日に戻る。

`Dashboard` は `atct:form-dirty` を購読し、いまの `handleGoalCreateDirtyChange` と
同じ扱いをする。**閉じたときに `false` を出すことを忘れない**
（アンマウント時の後始末が無いと、書きかけのまま閉じたフォームのせいで
更新が永久に保留される。同日それを踏んで直した）。

## 変えないもの

- フォームの中身（プロジェクト選択・題名・説明）と検証、`POST /api/goals`
- i18n のキー。足すときは en / ja 両方
- ヘッダーの既存の要素（ATCT のリンクと言語切り替え）の位置

## 検証

- **すべてのページ**（ダッシュボード・ゴール詳細・タスク詳細）でボタンが出ること
- 押すとダイアログが開き、Esc と背景クリックで閉じること
- 焦点がダイアログ内に移り、閉じたとき元のボタンに戻ること
- **作成するとダッシュボードの一覧に出ること**（実 DB のコピーで描画して確かめる）
- **入力中に更新が来ても文字が消えないこと**（否定側。これが本題）
- 入力が無いときは従来どおり自動で取り直すこと（否定側の逆）
- **書きかけのままダイアログを閉じたあと、次の更新で取り直されること**
- ダッシュボードの下部から消え、**同じフォームが 2 箇所に出ないこと**
