# タスクの順番を管理できるようにする

日付: 2026-08-20
ゴール: タスクは順番で管理するようにし、一覧ではその通りに並ぶようにしてほしい

## 解く問題

**順番は既に存在し、正しい順で並んでもいる。足りないのは「見えること」と
「テストで固定されていること」である。** 実物を確認した結果:

| 現状 | 場所 |
|---|---|
| `sort_order INTEGER NOT NULL` がある | `tasks` テーブル |
| 宣言時に配列の添字で決まる | `DeclareTasks` |
| クエリは `ORDER BY sort_order` で返す | `internal/store/queries/task.sql:15, 49, 66` |
| ゴール詳細の一覧は client 側でも `order` で並べ直す | `web/src/components/TaskTable.tsx:120` |
| **ダッシュボードの木は並べ替えていない** | `web/src/components/GoalTable.tsx:54`（`tasks.map`） |
| **順番の値が出ているのはモーダルだけ** | `web/src/components/TaskDetailModal.tsx:71-72` |
| **順番を変える経路が無い** | HTTP API・MCP のどちらにも存在しない |

つまり **画面から順番を知る手段がほぼ無い。** 一度宣言したら順番は変えられないが、
**人間はそれを問題としていない**（2026-08-20 の回答: 「入れ替え機能は不要。
順番が把握できるだけでよい」）。変更の経路は作らない。

ダッシュボードの木がサーバの返す順に依存しているのは、今は正しく動いているが
**テストで固定されていない。** サーバ側の `ORDER BY` を誰かが外したら黙って崩れる。

## 決定

### 一覧に順番を出す

ゴール詳細のタスク一覧に、先頭列として順番を出す（1 始まりで表示する。
`sort_order` は 0 始まりなので +1 する。**人間に 0 番を見せない**）。

ダッシュボードの木には出さない。**あちらは既に `├─` で順序を表現しており、
番号を足すと 1 行に情報が 2 つ増えて密度が落ちる**（`product-ui` の密度の指針）。

### client 側の並べ替えを両方に入れる

`GoalTable` にも `sort_order` での並べ替えを入れる。サーバが正しい順で返していても、
**「サーバがそう返すから」という暗黙の依存を残さない。** 2 箇所とも並べ、
両方をテストで固定する。

### 変えないもの

- `sort_order` の列名と型
- `DeclareTasks` が添字で順番を決める挙動
- `ORDER BY sort_order` のクエリ（消さない。client 側の並べ替えは二重の保険）
- `atct_task_update` の引数（`status` のみ。順番は別の経路にする）

## 検証

- ゴール詳細のタスク一覧に順番の列が出て、**1 始まり**であること（0 が出ない）
- **入力の順序を `sort_order` の昇順と食い違わせても、画面が昇順で並ぶこと**
  （client 側の並べ替えが実際に効いているかを見る。サーバ順に依存していないことの検査）
- **ダッシュボードの木も同じ条件で昇順に並ぶこと**（今テストが無い側）
- API 変更が不要であること（`api.ts` の `TaskView` には `order` が既にある）

フィクスチャはタスク 3 件以上にし、**入力を意図的に昇順でない順序で渡す。**
既に昇順の入力を渡すと、並べ替えをしない実装でも通る。

実 HOME（`~/.atct`）の daemon は止めない。

## やらないこと

- **順番を変える機能を作らない**（人間が 2026-08-20 に「入れ替え機能は不要。順番が
  把握できるだけでよい」と回答）。HTTP API も MCP ツールも足さない
- ドラッグ＆ドロップも上下ボタンも作らない
- ダッシュボードの木に番号を出す
