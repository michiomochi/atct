# ゴール詳細とタスク詳細モーダル

日付: 2026-08-19
ゴール: ゴール詳細とタスク詳細モーダルを指定のレイアウトにする

## 人間が指定したレイアウト

```
ゴール詳細ページ
  ゴールタイトル
  プロジェクト | 状態 | 更新日時
  完了報告          ← まだ無い場合は見出し自体も出さない
  タスク一覧（上から順番に）
    カラム: タイトル / 状態 / 更新日時
    タイトルをクリック → タスク詳細をモーダルで表示

タスク詳細モーダル
  タスクタイトル
  タスク説明
  回答フォーム      ← 回答待ちのものがある場合
  回答履歴          ← 質問 / 回答 / 回答日時 / 適用日時 / 回答変更ボタン
```

## 前の spec から変わった点

`2026-08-19-goal-detail-desktop.md` で私が提案した案から、人間が 2 つ変えた。

- **ゴール ID を属性に出さない。** 私は「CLI の引数に使う」として出す案を書いたが、採らない
- **3 列（いま / 判断待ち / 次）をやめ、1 本のタスク一覧にする。** 状態は列で表す

1 本の一覧にすると、**タスクの順序（宣言順）がそのまま画面の順序になる。** 3 列に分けると
順序が列ごとに切れるので、こちらの方が構造が読める。前の spec の 3 列の記述は破棄する。

最小幅 1120px と横スクロール（畳まない）は前の spec のまま有効。

## 決定

### タスクに説明のフィールドが無い

`domain.Task` は タイトル・状態・担当・触るファイル・順序・`declare_key`・claim した run・
日時を持つが、**説明を持たない。** `atct_task_declare` もタイトルの配列しか受け取らない。

**「タスク説明」の位置には、いま持っている属性を出す。** 触るファイル・担当・claim した run・
作成と更新の日時。説明の列を追加するのは、スキーマ移行と MCP ツールの引数と
エージェント側の書き方まで変わる別の作業なので、**まず今ある情報で使ってみて、
足りないと分かってから足す。**

### 完了報告が無いときは見出しも出さない

**空の枠に「まだありません」と書くのは画面を占有するだけで何も伝えない**（`product-ui` の
空状態の指針と、ダッシュボードで既に採った方針に揃える）。6 項目すべてが空なら
節ごと描画しない。

### モーダルは kumo の dialog を使う

`web/node_modules/@cloudflare/kumo/dist/components/dialog.js` が既にある。
**素の HTML と CSS で作り直さない**（`product-ui`: 成熟した部品があるならそれを標準にする）。

### 回答フォームと回答履歴のデータは既にある

`/api/goals/{id}` が返すもの:

| 使うもの | 中身 |
|---|---|
| `goal.tasks` | そのゴールのタスク（`order` 昇順） |
| `needs_decision` | open な決定を持つタスク（`open_decisions` 付き） |
| `decision_history` | 適用済みの決定（`task_id`・`answered_at`・`applied_at` を持つ） |
| `unattached_decisions` | タスクに紐づかない open な決定 |

**API の追加は不要。** モーダルは `task_id` で絞るだけでよい。

### 回答変更ボタンは revise に結ぶ

`POST /api/decisions/{id}/revise` が既にある（本文は `{"options": [...]}`）。
**確定した決定は覆さず、元の質問と選ばれた選択肢を引用した新しい決定を作る**
（2026-08-19 の回答「覆せない。異議は新しい決定として起こす」に従う）。

### 変えないもの

- `TaskTable`・`DecisionAnswerForm`・`DecisionHistoryTable` は再利用する
- 承認・却下のフォームの挙動を変えない
- `min-w-0` と `break-words` は残す（`ui.test.ts` が要求）
- i18n のキーは消さない。足すときは en / ja 両方

## 検証

- 完了報告が無いゴールで、見出しごと出ないこと
- タスクが `order` 昇順で 1 本に並ぶこと
- タイトルを押すとモーダルが開き、Esc と背景クリックで閉じること
- **回答待ちの決定を持つタスクでは回答フォームが出て、無いタスクでは出ないこと**（否定側）
- 回答履歴に 質問 / 回答 / 回答日時 / 適用日時 が出ること
- モーダルを開いたとき焦点がモーダル内に移り、閉じたとき元のボタンに戻ること
- 1280px で崩れないこと

実 HOME（`~/.atct`）の daemon は止めない。
