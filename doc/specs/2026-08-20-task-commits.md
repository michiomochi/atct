# タスクにコミットを紐づけ、変更内容を読めるようにする

日付: 2026-08-20
ゴール: 各タスク毎にコミットするようにし、各タスクにコミットを紐付けられるようにして。
紐付けられたコミットをタスク詳細で表示し、コミットの変更内容をレビューできるようにしたい。

## 解く問題

**タスクが done になったとき、何が変わったのかを追う経路が無い。**
`git log` を人間が読み、コミットメッセージからタスクを推測することになる。

同日、私は 29 コミットを積み、タスクを 40 件以上閉じた。**どのコミットがどのタスクか、
記録は残っていない。**

## 測ったこと

### daemon が git を実行するのは新しい依存ではない

**タスクの説明に「新しい依存である」と書いたが、誤りだった。**
`internal/store/project.go:43` と `:67` が既に `git` を実行している
（`normalizeWorktreePath`。worktree を主リポジトリに写すため）。

### コミット 1 件の差分の大きさ（同日の 11 件）

```
最小    4 行 /   356 バイト
中位   57 行 /  3463 バイト
最大 1103 行 / 42014 バイト
```

**42KB のものがある。** 保存するかどうかの判断はこの数字で決める。

## 決定

### 保存するのは SHA・メッセージ・変更の要約。差分は保存しない

| 保存する | 理由 |
|---|---|
| SHA | 紐づけの本体 |
| メッセージの 1 行目 | **履歴から消えても何をしたかは残る** |
| ファイル数・追加行・削除行 | 一覧で規模が分かる。`git` を叩かずに出せる |

**差分は保存しない。** 42KB × コミット数が `pending` のたびに読まれる DB に載る。
**差分はコミットから決まるので、読むときに `git` で取れば足りる。**

### 差分は読むときに git で取る

`projects.root_path` は分かっている。`git show --numstat` と `git show` を使う。
**新しい依存ではない**（上で測ったとおり）。

### 1 タスクに複数のコミットを許す

**1 タスク 1 コミットを強制しない。** 実際に「実装 → テスト → 修正」で分かれる。
**強制すると、まとめるために不要な `amend` を誘発する**（履歴の書き換えは
取り消せない操作なので、仕組みがそれを誘発してはいけない）。

### 履歴から消えた SHA は消さない

`rebase` や `amend` で SHA が消えることはある。**そのとき紐づけを削除しない。**

読むときに `git cat-file -e <sha>` で確認し、無ければ
**保存したメッセージと要約を出し、「この SHA はもう履歴に無い」と添える。**

**作業が行われた事実は消えていない。** 参照が切れただけである。

### 差分の表示には上限を置き、省略を伝える

**回答履歴で同じ問題を踏んでいる**（上限 20 件がゴール単位でかかり、
省略件数が他タスクの分を数えていた）。

- **ファイルの一覧は常に全部出す**（何が変わったかは省略しない）
- 差分の本文に行数の上限を置き、**超えた分を「N 行省略」と出す**
- **モーダルにしない。** 同日、縦に伸びて見切れるモーダルをページに移した

### 紐づけ忘れを検知する

**全タスクが done なのにコミットが 1 件も紐づいていないゴール**を検知する。
今日入れた 3 条件と同じ形。**紐づけたら消える**（収束する）。

## 変えないもの

- `atct_task_update` の既存の呼び出しが壊れないこと（コミットは省略可能な引数）
- 空のときは節ごと描画しない（既存の方針）

## 検証

- タスクに複数のコミットを紐づけられること
- **履歴から消えた SHA でも、メッセージと要約が出ること**（否定側）
- 差分がファイル一覧 + 上限付きの本文として読めること
- **上限を超えたとき省略が伝わること**
- **コミットを渡さずに done にしたタスクが検知に出ること**、
  **紐づけると消えること**（収束）
- 実 DB のコピーで、実際のコミットを紐づけて描画で読めること
