## 発端

同日、検知条件を 9 つ列挙して条件 5 だけを実装した。**その後、列挙した隙間のうち 1 つと、
列挙していなかった隙間 1 つを、実際に踏んだ。**

| 隙間 | どう見つかったか |

| 条件 8: 全タスク done なのに完了報告なし | **人間が画面を見て指摘した。** ゴール `38a79d54` が 7 タスク done で active のままだった |
| claim を外したタスクが doing のまま | **commander が引き取りの経路を実測して見つけた** |

**列挙しただけでは防げない。** 1 つ目は列挙済みで未実装、2 つ目は列挙にすら無かった。

## claim を外したタスクが doing のまま残る

`ReleaseTask`（`internal/store/queries/task.sql`）は `claimed_by` を空にするだけで
`status` を触らない。

```sql
UPDATE tasks SET claimed_by = '', claimed_at = NULL, updated_at = ? WHERE id = ?;
```

結果、**`status='doing'` かつ `claimed_by=''`** が作れる。実測（実 DB のコピー、
39 時間放置された claim を `POST /api/tasks/<id>/release` で解放）:

```
HTTP 200
status=doing  claimed_by=[]
```

**そしてどの検知条件にも出ない。**

| 条件 | 出るか | 理由 |
|---|---|---|
| 3（自分の claim が開いている） | 出ない | claim が無い |
| 5（未着手のタスクがある） | 出ない | `doing` は未着手ではない |
| 7（放置された claim） | 出ない | claim が無い |

**誰も作業していないのに進行中に見え、誰も指摘しない。** 画面から `release` を押せば起きる。

## 未決 1: `release` が `status` をどう扱うか

commander の推奨は **`todo` に戻す。**

`claim` の無い `doing` は意味を持たない状態であり、`release` は人間が放置 claim を
引き取るための操作なので、`todo` に戻す方が意図に合う。

**代償**: `release` の意味が「claim を外す」から「claim を外して未着手に戻す」に変わる。
呼び出し側を確認してから変える。

**それでも検知は足す。** 何かの拍子でこの状態ができたときに、
`pending` か SSE のどちらかに出るようにする。**入口を塞ぐだけでは、
別の経路でできた場合に気づけない。**

## 未決 2: 全部 `dropped` のゴールを条件 8 に含めるか

commander の推奨は **含めない。別の条件として分ける。**

同日、ゴール `5f53dacd`（言い直しに置き換わったモーダルのゴール）で全タスクを `dropped` に
して完了報告を出した。あれは正しい流れだったが、**「作業しないと決めたゴール」に
完了報告を要求するのは筋が違う。**

ただし**放置と区別がつかない。** 全部 `dropped` で完了報告も無いゴールは
「やらないと決めて閉じ忘れた」状態である。**別の条件として分ける方が正確で、
文言も変えられる**（「完了報告を出せ」ではなく「取り下げたなら閉じるか、
やり直すなら宣言し直せ」）。

## 収束すること

どちらの条件も、対応すれば消える。

| 条件 | 消える操作 |
|---|---|
| 全タスク done で完了報告なし | `atct_goal_complete` を呼ぶ |
| claim の無い `doing` | `status` を変える（`todo` か `done`） |

**条件 5 で収束を実測しており、収束しない条件は毎ターン邪魔をして役に立たなくなる**
（2026-08-18 に「未 claim のタスクがある」を外した判断がそれ）。

## 検証

- **否定側**: 完了報告を出したゴールでは条件が出ないこと
- **否定側**: claim の無い `doing` を `todo` にしたら条件が出ないこと
- **否定側**: 他プロジェクトのゴールで出ないこと（プロジェクト 2 件で測る）
- 肯定側: それぞれの状態を作って出ること
- **`release` を押しても claim の無い `doing` が残らないこと**（入口を塞いだ確認）
