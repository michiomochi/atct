# claim を持たずに委譲できないようにする

日付: 2026-08-20
ゴール: commander が委譲時に claim をつけなかったことについて根本的な対策をして。
claim をつけないと委譲できないような仕組みにしたい

## 発端

2026-08-20、commander が 3 台の executor に作業を渡し、**11 件のタスクを claim せずに
放置した。** Stop フックはそれを「未着手」として並べ、その裏で executor はまさにその
ファイルを編集していた。**ダッシュボードが嘘をつき、人間はその嘘を前提に予定を立てる。**

## 指示では直らない

Claude Code の文書がそう書いている。

> Claude treats them as context, not enforced configuration. To block an action
> regardless of what Claude decides, use a PreToolUse hook instead.

**私は「委譲する前に claim する」を知っていて、それでも 11 件で破った。** 同じ形の指示を
足す案は採らない。

## 決定

### PreToolUse フックで Bash を見る

`herdr agent prompt` に**依頼書のパス（`req-*.md` に一致するもの）が含まれているとき**だけ
委譲と見なす。そのとき `atct claim-check any` を呼び、どのタスクも claim されていなければ
exit 2 で止める。

### 対象を狭くする理由

同日の `herdr agent prompt` は 19 回以上あったが、**委譲は 8 回で、残りは差し戻しへの回答・
訂正・情報の伝達・取り下げだった。** それらを止めるとツールが使えなくなる。

### 止めるときは何をすればよいかを書く

exit 2 のメッセージに「claim してから再実行する」ことと、その手順を書く。
**理由だけ書いて手順を書かないと、止められた側は同じことを繰り返す。**

### この仕組みの限界（先に書く）

**依頼をファイルにせず、プロンプトに直接書けばこのフックは素通りする。**
閉じたのは「実際に通った経路」であって、すべての経路ではない。

判定を「`herdr agent prompt` すべて」に広げれば穴は塞がるが、上の 11 回を全部
止めることになる。**狭く始めて、素通りが実際に起きたら広げる。**

## 収束すること

claim すれば通る。**止まったまま何をしても通らない形にしない。**

## 検証

- **claim を持たずに依頼書を渡すと止まること**（肯定側）
- **claim を持っていれば通ること**（否定側）
- **依頼書を含まない `herdr agent prompt` が止まらないこと**（否定側。これが本題。
  差し戻しへの回答が止まるとツールが使えなくなる）
- 止まったときのメッセージに手順が書かれていること

## 状態

フックは chezmoi のソース（`dot_claude/hooks/executable_claim-before-delegate.sh`）に
書いてあるが、**まだ適用していない。** 適用はエージェント自身の設定変更なので人間の承認を待つ。

適用の前に `chezmoi re-add ~/.claude/settings.json` が必要である。実体側で `autoMode` が
書き足されており、そのまま `chezmoi apply` すると消える。**別のセッションが同じ
ディレクトリに 3 件の未適用変更（orchestration スキル関連）を持っているので、
それらは触らない。**

## この仕組みは atct のリポジトリから出た（2026-08-22）

**この spec が説明するフックは、もう atct のリポジトリには無い。**

人間の差し戻し: 「atct を使用しているのは私の環境のみなので atct に herdr の依存を
いれないで。」

atct は GitHub Releases と homebrew cask で公開している道具で、herdr はこの環境の
多重化ツールである。フックは `herdr agent prompt` を判定条件に持ち、`script/delegate.sh` は
`herdr agent prompt` を直接叩いていた。どちらも、公開する道具が特定の環境のツールを
前提にする形だった。

置き場の判定を 2 回間違えた記録として残す。

1. 最初は共有 dotfiles（`~/.claude/hooks/`）に置いた。**全プロジェクトの全 Bash 呼び出しに
   乗るのに、内容は atct 固有**だった。dotfiles 側で外された（e689dd6）。
2. 次に atct のリポジトリに置いた（dc62545）。「atct 固有だから atct へ」という理由は
   半分しか合っていない。**このフックは atct と herdr の両方を前提にする。**
   atct は公開物なので、herdr を知ってはいけない。

正しい置き場は、atct と herdr の両方が正当に共存する場所、つまり**この環境の dotfiles**
である。「atct 固有か」ではなく「**公開物か、環境の設定か**」で判定すべきだった。

フック本体と判定の設計（`req-*.md` を含む `herdr agent prompt` だけを委譲と見なす、
`claim-check` が通れば素通りさせる、判定できないときは通す）はこの spec のままで、
実装は dotfiles 側へ渡した。実測した終了コードも残す。依頼書のパスを含まない返信は 0、
別ツールの呼び出しは 0、claim 無しの委譲は 2、claim 有りは 0。
