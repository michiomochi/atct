# ゴール詳細を PC 前提の画面にする

日付: 2026-08-19
ゴール: ゴール詳細を PC 前提の画面に作り直す

## 解く問題

人間から「スマホ対応は不要なので PC に特化した UI で作り直してほしい」という指示。

現状の `GoalDetail.tsx`（257 行）は、狭い画面で 1 列に畳む前提で組まれている。
`xl:grid-cols-3` なので、**1280px 未満では 3 つのタスク列が縦に積む。** 実際には
1280px 以上で見るのに、狭い画面のために列を畳む余地を残している。

なおレスポンシブの指定はプロジェクト全体で 3 箇所しかない（`GoalDetail` の
`xl:grid-cols-3` と `sm:grid-cols-*`、他 1）。**指定を消すだけの作業ではなく、
PC の広さを前提に情報の置き方を決め直すのが本題である。**

## 決定

### 最小幅を決め、それ以下は横スクロールにする

**本文の最小幅を 1120px にする。** それより狭いときは畳まず、横スクロールさせる。

畳む代わりに横スクロールを選ぶ理由は、**畳むと「どこに何があるか」が幅によって変わり、
画面を覚えられなくなる**ため。PC 専用と決めたなら、配置は固定した方が速く読める。

### 3 列を常時にする

`xl:grid-cols-3` の条件を外し、**常に 3 列**にする（いま / 判断待ち / 次）。
幅が足りないときは上の横スクロールで見せる。

### ヘッダにゴールの属性をまとめる

いまタイトルの下に project 名が 1 行あるだけ。**PC の横幅を使い、属性を横並びにする。**

| 出すもの | 理由 |
|---|---|
| プロジェクト | どのリポジトリのゴールか |
| 状態 | 進行中 / 完了 |
| 更新日時 | 最後に動いた時刻 |
| ゴール ID | **リンクの共有と `atct` の CLI 引数に使う。ここは UUID を出す** |

ダッシュボードでは UUID を消したが、**詳細ページは 1 件を特定して作業する場所なので
ID が要る。** 出す場所を一箇所に集めるのが、消すよりも筋が通る。

### 完了報告と承認は本文の下に全幅で置く

6 項目の報告は 1 項目が最大 2000 文字ある。**列に押し込むと 1 行あたりの文字数が
足りず読めない。** 全幅で、上限 `max-w-[80ch]` を置く（読みやすい行長）。

承認フォームは報告の直下に置く。**読んでから押す順序を画面の順序と一致させる。**

### 決定履歴は最下部

過去の記録なので、いま判断するものより下に置く。

### 変えないもの

- **既存の部品（`TaskTable`・`DecisionHistoryTable`・`Section`）を再利用する。**
  作り直すのはレイアウトであり、部品ではない
- **承認・却下のフォームの挙動を変えない。** 押せるボタンと送信先はそのまま
- `min-w-0` と `break-words` は残す（`ui.test.ts` が要求している。長い文字列が
  レイアウトを壊さないための指定で、PC 専用にしても必要）
- i18n のキーは消さない。足すときは en / ja 両方

## 検証

- 1280px と 1440px で、3 列が横に並ぶこと
- **1120px 未満では畳まず横スクロールになること**（本文が縦 1 列にならない）
- 完了報告の行長が 80ch を超えないこと
- 承認フォームが従来どおり動くこと（`ui.test.ts` の完了報告・承認のテストが通る）
- `pnpm test` が通ること

実 HOME（`~/.atct`）の daemon は止めない。画面の確認は一時 HOME か、
コミット後に commander が反映して行う。

## やらないこと

- 狭い画面向けの代替レイアウトを作らない（PC 専用と決めた）
- 部品の中身を作り直さない
