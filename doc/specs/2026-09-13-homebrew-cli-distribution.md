# Homebrew CLI Distribution

## Goal

Install and update the `atct` command through the existing
`michiomochi/homebrew-tap` Cask. Keep the Claude Code and Codex plugins as the
distribution for hooks, MCP configuration, and skills, but remove their binary
download, checksum, cache, and launcher responsibilities.

## Distribution boundary

The supported CLI installation is:

```sh
brew install --cask michiomochi/tap/atct
```

The Cask installs both `atct` and `atct-mcp` from the release archive. It is
generated by GoReleaser into the existing `michiomochi/homebrew-tap`; no new tap
or Formula is introduced.

The plugin does not install, download, cache, or create a launcher for either
binary. Claude hooks invoke the installed `atct` on `PATH`; Codex monitors pass
their running CLI path as `ATCT_BIN`. `atct-mcp` remains in the Cask for
non-plugin MCP clients; the plugins continue to use the existing HTTP MCP
endpoint.

## Plugin compatibility

Plugin and CLI releases may be upgraded separately, so Claude hooks must reject
an absent or older CLI before issuing workflow commands. The CLI exposes its
release version through a normal command. Each Claude hook compares it with the
plugin's declared version and emits one actionable message:

```text
ATCT: install or upgrade the CLI with: brew install --cask michiomochi/tap/atct
```

or, when a CLI is installed but older:

```text
ATCT: upgrade the CLI with: brew upgrade --cask michiomochi/tap/atct
```

After either condition, the hook exits without starting a daemon or applying a
permission decision. Equal or newer CLI versions continue normally. Codex
monitor hooks use their injected CLI path and emit the installation instruction
when it is absent. These checks are not resolvers: they perform no network
access, cache management, archive extraction, launcher creation, or file
writes.

## Removed behavior

Remove `bin/atct`, `bin/atct-mcp`, and `bin/_resolve`, together with the tests
that only verify release downloading, checksum verification, cache pruning, and
the `~/.local/bin/atct` launcher. Remove their release-script invocations and
the version bump that rewrites `_resolve`.

Hook tests remain and exercise the real hook behavior through a fake `atct` on
`PATH`: available/current CLI runs the existing commands, missing or stale CLI
emits the relevant install instruction and performs no workflow action.

## Release flow and documentation

Restore the prior GoReleaser `homebrew_casks` configuration for the existing
tap, including the two installed binaries and macOS quarantine removal. A
release publishes the Cask after the version tag and archives are published.

README installation separates the two one-time steps: install the CLI through
Homebrew, then install the plugin for the selected AI harness. It documents
`brew upgrade --cask michiomochi/tap/atct` for CLI updates and removes all
references to `~/.atct/bin`, the resolver, and the generated launcher.

## Acceptance criteria

1. GoReleaser is configured to update `michiomochi/homebrew-tap` with a Cask
   that installs both release binaries for macOS and Linux architectures.
2. No plugin-owned binary resolver, cache, downloader, checksum verifier, or
   global launcher remains.
3. Claude hooks use the Homebrew-installed `atct` from `PATH`, fail closed with
   an actionable command when it is missing or older than the plugin, and
   preserve the existing behavior when it is current. Codex monitor hooks keep
   their direct CLI path and give the same installation instruction when absent.
4. The release script no longer reads or rewrites a resolver version and no
   longer runs resolver-only tests.
5. README gives the Cask command before plugin setup and describes independent
   CLI updates.
